# Tank Game — Authoritative Node.js Server

هذا السيرفر مخصص للعبة Tank Game الحالية التي تتصل عبر WebSocket.

## ماذا يفعل؟

- غرفة PvP بحد أقصى لاعبين.
- إنشاء غرفة بكود من 6 رموز.
- الانضمام بالكود.
- Quick Match: يضع لاعبين متاحين في غرفة واحدة تلقائيًا.
- Ready: لا تبدأ المعركة قبل جاهزية اللاعبين.
- Host فقط يستطيع بدء المعركة.
- يمنع دخول لاعب ثالث.
- يمنع تعديل إعدادات الغرفة بعد بدء المعركة.
- يملك السيرفر هوية اللاعب والغرفة والـ role.
- يتحقق من ملكية IDs للوحدات والمباني.
- يتحقق من الحدود، HP، المال، أنواع الوحدات، وعددها.
- يمنع العميل من إرسال حالة لاعب آخر.
- يمنع زيادة HP بشكل غير منطقي بين لقطات الحالة.
- يحدد معدل إرسال الحالة.
- يرفض الرسائل غير المعروفة.
- heartbeat وتنظيف الاتصالات الميتة.
- Health endpoint.

## التثبيت

```bash
npm install
npm start
```

الافتراضي:

- HTTP: `http://localhost:10000/health`
- WebSocket: `ws://localhost:10000/ws`

في Render أو أي استضافة مشابهة، يكفي تشغيل:

```bash
npm start
```

والسيرفر سيستخدم `process.env.PORT`.

## ربط اللعبة

في HTML يجب أن يكون:

```js
const PVP_SERVER = 'wss://YOUR-SERVER-DOMAIN/ws';
```

مثال:

```js
const PVP_SERVER = 'wss://tank-game-server-o650.onrender.com/ws';
```

## Quick Match

السيرفر يدعم:

```js
send({
  type: 'quick_match',
  name: pvpMyName,
  settings: {
    money: pvpMoney,
    color: pvpColor,
    colorName: pvpColorName
  }
});
```

السيرفر ينتظر لاعبين ثم يضعهما في غرفة واحدة تلقائيًا.

## ملاحظة مهمة عن "الحكم الكامل"

النسخة الحالية من لعبة المتصفح تنفذ الحركة والقتال محليًا ثم ترسل `state` إلى السيرفر. لذلك هذا السيرفر يعمل كـ **حكم/محقق مركزي للحالة المرسلة**، وليس محرك فيزياء كاملًا للسيرفر.

لكي يصبح السيرفر حكمًا مطلقًا 100% على الحركة والرصاص والضرر والشراء والنفط والبناء، يجب تعديل HTML ليُرسل أوامر فقط مثل:

- `move`
- `attack`
- `build`
- `buy_unit`
- `capture_oil`
- `stop`
- `defend`

ثم يقوم Node.js بحساب النتيجة وتوزيع الحالة الناتجة على اللاعبين.

لا ينبغي اعتبار أي قيمة يرسلها المتصفح مثل HP أو المال أو موقع الوحدة حقيقة نهائية في ذلك التصميم.

## قوانين المباراة الحالية

1. لاعبان فقط في المباراة.
2. اللاعب الثالث مرفوض.
3. المضيف وحده يبدأ المعركة.
4. يجب أن يكون اللاعبان جاهزين.
5. بعد البداية تُقفل إعدادات الغرفة.
6. كل وحدة يجب أن يكون ID الخاص بها تابعًا لصاحبها.
7. لا يسمح بتكرار IDs.
8. لكل نوع وحدة حد أعلى.
9. HP لا يمكن أن يتجاوز Max HP.
10. المال لا يمكن أن يكون سالبًا.
11. المواقع يجب أن تكون ضمن حدود العالم.
12. الرسائل المجهولة/غير المدعومة مرفوضة.
13. إرسال الحالة بسرعة زائدة يؤدي إلى الرفض.
14. تكرار الحالات غير القانونية يؤدي إلى قطع الاتصال.
15. انقطاع اللاعب يخرج من الغرفة ويبلغ اللاعب الآخر.
